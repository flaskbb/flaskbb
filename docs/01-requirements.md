# Требования к проекту FlaskBB

Версия документа: 1.0

## 1. О приложении

### 1.1. Назначение приложения

FlaskBB — веб-приложение для создания и управления интернет-форумом. Оно предоставляет пользователям возможность общаться, создавать темы обсуждений, публиковать сообщения, искать информацию и управлять содержимым форума.

Проект основан на Flask и использует модульную архитектуру. В рамках лабораторной работы рассматривается существующий проект FlaskBB и его дальнейшее развитие.

### 1.2. Роли пользователей

| Роль | Описание |
|---|---|
| Гость | Неавторизованный посетитель, который может просматривать доступные разделы форума и темы |
| Зарегистрированный пользователь | Пользователь с учётной записью, который может создавать темы, публиковать сообщения и управлять своим профилем |
| Модератор | Пользователь, имеющий права на управление содержимым форума и соблюдением правил общения |
| Администратор | Пользователь с расширенными правами управления форумом, пользователями, группами и настройками |

### 1.3. Основные термины

| Термин | Определение |
|---|---|
| Форум | Раздел, в котором размещаются темы обсуждений |
| Категория | Группа форумов, объединённых общей тематикой |
| Тема | Обсуждение, созданное пользователем внутри форума |
| Сообщение | Запись пользователя в теме обсуждения |
| Учётная запись | Набор данных, позволяющих идентифицировать пользователя |
| Модерация | Управление темами и сообщениями для соблюдения правил форума |

### 1.4. Существующие возможности

На момент начала работы FlaskBB поддерживает регистрацию и аутентификацию пользователей, просмотр форумов, создание тем и сообщений, управление профилем, поиск и административные функции. Часть возможностей зависит от роли и прав пользователя.

## 2. Требования к функционалу

Приоритеты:
- Обязательно — функция должна входить в объём работ текущего семестра.
- Желательно — функция рассматривается при наличии времени.
- Потом — функция может быть реализована в дальнейшем.

Состояния:
- Уже есть — возможность реализована в исходном проекте.
- Нужно доработать — существующая возможность требует изменений.
- Нужно сделать — возможность отсутствует и должна быть реализована.

### FR-1. Регистрация пользователей

Пользователь в роли гостя может зарегистрировать учётную запись для получения доступа к функциям зарегистрированного пользователя.

- Приоритет: обязательно.
- Состояние: уже есть.
- Критерий выполнения: пользователь может отправить регистрационные данные, после успешной регистрации в системе создаётся учётная запись, а при некорректных данных отображается сообщение об ошибке.

### FR-2. Аутентификация пользователей

Зарегистрированный пользователь может войти в свою учётную запись и завершить сеанс работы.

- Приоритет: обязательно.
- Состояние: уже есть.
- Критерий выполнения: пользователь с корректными учётными данными получает доступ к функциям своей роли, а после выхода его авторизованный сеанс завершается.

### FR-3. Просмотр форумов

Пользователь может просматривать доступные категории, форумы и размещённые в них темы.

- Приоритет: обязательно.
- Состояние: уже есть.
- Критерий выполнения: пользователь может открыть главную страницу форума, перейти в категорию и форум, просмотреть список доступных тем.

### FR-4. Создание и редактирование тем

Зарегистрированный пользователь может создавать темы в доступных ему форумах и редактировать собственные темы.

- Приоритет: обязательно.
- Состояние: уже есть.
- Критерий выполнения: после отправки корректных данных новая тема появляется в выбранном форуме, а автор может изменить её содержимое при наличии соответствующих прав.

### FR-5. Публикация и редактирование сообщений

Зарегистрированный пользователь может публиковать сообщения в темах и редактировать собственные сообщения при наличии соответствующих прав.

- Приоритет: обязательно.
- Состояние: уже есть.
- Критерий выполнения: сообщение сохраняется и отображается в выбранной теме; при редактировании отображается обновлённый текст.

### FR-6. Поиск информации

Пользователь может выполнять поиск по доступным ему пользователям, темам и сообщениям форума.

- Приоритет: желательно.
- Состояние: уже есть.
- Критерий выполнения: при вводе поискового запроса система отображает соответствующие найденные результаты либо сообщает, что результаты отсутствуют.

### FR-7. Управление профилем

Зарегистрированный пользователь может просматривать и изменять доступные настройки собственной учётной записи.

- Приоритет: желательно.
- Состояние: уже есть.
- Критерий выполнения: пользователь может открыть настройки профиля, изменить разрешённые данные и увидеть сохранённые изменения.

### FR-8. Модерация форума

Модератор или администратор может выполнять разрешённые действия по управлению темами и сообщениями форума.

- Приоритет: обязательно.
- Состояние: уже есть.
- Критерий выполнения: пользователь с соответствующими правами может выполнить доступное действие модерации, а пользователь без необходимых прав не может выполнить это действие.

## 2.1. Нефункциональные требования

### NFR-1. Совместимость с платформами

Веб-приложение должно быть доступно через современный браузер на настольных компьютерах.

Критерий проверки: основные страницы приложения открываются и отображаются в актуальных версиях Chrome, Firefox и Edge.

### NFR-2. Защита учётных записей

Приложение должно обеспечивать аутентификацию пользователей и ограничивать доступ к функциям в соответствии с их правами.

Критерий проверки: неавторизованный пользователь не может выполнять действия, требующие авторизации, а пользователь не может выполнять административные действия без соответствующих прав.

### NFR-3. Защита конфигурационных данных

Секретные параметры приложения и учётные данные внешних сервисов не должны попадать в публичный репозиторий.

Критерий проверки: локальные конфигурационные файлы с секретами исключены из Git, а в репозитории отсутствуют реальные пароли и секретные ключи.

### NFR-4. Сопровождаемость

Исходный код и настройки проекта должны быть организованы так, чтобы разработчики могли находить необходимые модули и запускать проверки.

Критерий проверки: структура проекта описана в документации, зависимости зафиксированы, а тесты запускаются по документированной команде.

### NFR-5. Сохранность данных

Приложение должно сохранять данные пользователей, форумов, тем и сообщений в настроенном хранилище данных.

Критерий проверки: после сохранения данных и повторного открытия соответствующего раздела ранее созданные записи остаются доступными.

## Сведения о документе

Требования являются исходной версией спецификации проекта. Номера FR и NFR сохраняются при последующих изменениях документации, реализации и тестов.

## 3. Пользовательские сценарии

### 3.1. Перечень пользовательских сценариев

**US-1. Регистрация пользователя (FR-1)**

- Роль: гость.
- Предусловие: пользователь не авторизован, регистрация включена.
- Входные данные: имя пользователя, адрес электронной почты, пароль, подтверждение пароля, выбранный язык, принятие условий использования.
- Основной поток:
  1. Пользователь открывает страницу регистрации.
  2. Заполняет обязательные поля.
  3. Подтверждает пароль и принимает условия использования.
  4. Отправляет форму.
  5. Система проверяет данные и создаёт учётную запись.
- Ожидаемый результат: учётная запись создана, пользователь перенаправлен на главную страницу форума.
- Состояние: уже есть.

**US-2. Вход и выход из учётной записи (FR-2)**

- Роль: зарегистрированный пользователь.
- Предусловие: пользователь имеет учётную запись.
- Входные данные для входа: имя пользователя или email, пароль.
- Основной поток:
  1. Пользователь открывает страницу входа.
  2. Вводит имя пользователя или email и пароль.
  3. Отправляет форму.
  4. Система проверяет учётные данные и выполняет вход.
  5. Для выхода пользователь выбирает соответствующее действие.
- Ожидаемый результат: после успешного входа пользователь получает доступ к функциям своей роли; после выхода сессия завершается, отображается главная страница форума.
- Состояние: уже есть.

**US-3. Просмотр категорий, форумов и тем (FR-3)**

- Роль: гость или зарегистрированный пользователь.
- Предусловие: в системе существуют доступные категории и форумы.
- Входные данные: выбранная категория, форум или тема.
- Основной поток:
  1. Пользователь открывает главную страницу форума.
  2. Выбирает категорию или форум.
  3. Просматривает список тем.
  4. Выбирает тему для просмотра.
- Ожидаемый результат: система отображает доступные пользователю разделы, список тем и сообщения выбранной темы.
- Состояние: уже есть.

**US-4. Создание и редактирование темы (FR-4)**

- Роль: зарегистрированный пользователь.
- Предусловие: пользователь авторизован и имеет право создавать или редактировать темы в выбранном форуме.
- Входные данные: идентификатор форума или темы, заголовок темы, текст первого сообщения.
- Основной поток:
  1. Пользователь открывает нужный форум.
  2. Выбирает создание новой темы.
  3. Вводит заголовок и текст.
  4. Отправляет форму.
  5. Система проверяет данные и сохраняет тему.
  6. При редактировании пользователь открывает существующую тему, изменяет данные и сохраняет их.
- Ожидаемый результат: новая тема появляется в выбранном форуме либо изменения существующей темы сохраняются.
- Состояние: уже есть.

**US-5. Публикация и редактирование сообщений (FR-5)**

- Роль: зарегистрированный пользователь.
- Предусловие: пользователь авторизован и имеет право отвечать в выбранной теме.
- Входные данные: идентификатор темы, текст сообщения.
- Основной поток:
  1. Пользователь открывает тему.
  2. Выбирает добавление ответа.
  3. Вводит текст сообщения.
  4. Отправляет форму.
  5. Система проверяет и сохраняет сообщение.
  6. При необходимости пользователь открывает собственное сообщение для редактирования и сохраняет изменения.
- Ожидаемый результат: сообщение появляется в теме либо его изменённая версия отображается вместо предыдущей.
- Состояние: уже есть.

**US-6. Поиск пользователей, тем и сообщений (FR-6)**

- Роль: пользователь.
- Предусловие: доступен соответствующий поисковый функционал.
- Входные данные: поисковый запрос.
- Основной поток:
  1. Пользователь открывает страницу поиска.
  2. Вводит поисковый запрос.
  3. Отправляет форму.
  4. Система выполняет поиск по выбранному типу данных.
- Ожидаемый результат: система отображает найденные результаты, соответствующие запросу.
- Состояние: уже есть.

**US-7. Управление профилем пользователя (FR-7)**

- Роль: зарегистрированный пользователь.
- Предусловие: пользователь авторизован.
- Входные данные: изменяемые сведения профиля и настройки учётной записи.
- Основной поток:
  1. Пользователь открывает страницу своего профиля.
  2. Выбирает редактирование сведений.
  3. Изменяет доступные поля.
  4. Сохраняет изменения.
- Ожидаемый результат: система сохраняет допустимые изменения и отображает обновлённые сведения профиля.
- Состояние: уже есть.

**US-8. Модерация содержимого форума (FR-8)**

- Роль: модератор или администратор.
- Предусловие: пользователь авторизован и обладает необходимыми правами модерации.
- Входные данные: выбранная тема или сообщение, действие модерации.
- Основной поток:
  1. Модератор открывает форум или тему.
  2. Выбирает объект для модерации.
  3. Выбирает действие: заблокировать, разблокировать, скрыть, показать, переместить или удалить тему либо сообщение.
  4. Система проверяет права пользователя.
  5. Система выполняет действие и отображает результат.
- Ожидаемый результат: выбранный объект получает соответствующее состояние либо удаляется или перемещается.
- Состояние: уже есть.

### 3.2. Подробные сценарии с проверкой ошибок

#### Сценарий US-1. Регистрация пользователя

**Успешный вариант**

Входные данные:
- Имя пользователя: `student14`
- Email: `student14@example.com`
- Пароль: `StrongPass123!`
- Подтверждение пароля: `StrongPass123!`
- Условия использования: приняты.

Ожидаемый результат:
- Форма проходит проверку.
- Система создаёт новую учётную запись.
- Пользователь перенаправляется на главную страницу форума.

**Ошибочный вариант**

Входные данные:
- Имя пользователя: пустое поле.
- Email: `student14@example.com`.
- Пароль: `StrongPass123!`.
- Подтверждение пароля: `DifferentPass123!`.

Ожидаемое поведение:
- Для имени пользователя отображается сообщение `A valid username is required`.
- Для несовпадающих паролей отображается сообщение `Passwords must match.`
- Регистрация не выполняется.
- Пользователь остаётся на странице регистрации и может исправить данные.

Другие проверяемые ошибки:
- Некорректный email: `Invalid email address.`
- Непринятые условия использования: `Please accept the TOS.`
- Повторяющееся имя пользователя или email: система возвращает ошибки проверки регистрации; конкретный текст зависит от результата проверки RegistrationService.

#### Сценарий US-2. Вход пользователя

**Успешный вариант**

Входные данные:
- Логин: `student14`.
- Пароль: `StrongPass123!`.

Ожидаемый результат:
- Система проверяет учётные данные.
- Выполняется вход пользователя.
- Пользователь перенаправляется на главную страницу форума либо на запрошенную страницу.

**Ошибочный вариант**

Входные данные:
- Логин: пустое поле.
- Пароль: пустое поле.

Ожидаемое поведение:
- Для логина отображается сообщение `Please enter your username or email address.`
- Для пароля отображается сообщение `Please enter your password.`
- Вход не выполняется.
- Пользователь остаётся на странице входа.

При неверном пароле или неизвестном пользователе система также не выполняет вход и отображает причину отказа, возвращённую механизмом аутентификации.

#### Сценарий US-4. Создание темы

**Успешный вариант**

Предусловие: пользователь авторизован и имеет право создавать темы в выбранном форуме.

Входные данные:
- Форум: `Общие обсуждения`.
- Заголовок: `Обсуждение учебного проекта`.
- Текст первого сообщения: `Предлагаю обсудить этапы разработки проекта.`

Ожидаемый результат:
- Форма проходит проверку.
- Система сохраняет тему и первое сообщение.
- Пользователь перенаправляется на страницу созданной темы.

**Ошибочный вариант**

Входные данные:
- Заголовок: пустое поле.
- Текст сообщения: пустое поле.

Ожидаемое поведение:
- Для заголовка отображается сообщение `Please choose a title for your topic.`
- Для текста отображается сообщение `You cannot post a reply without content.`
- Тема не создаётся.
- Пользователь остаётся на странице создания темы и может исправить данные.

Если пользователь не авторизован или не имеет необходимых прав, создание темы не выполняется.

## 4. Модели системы

Все диаграммы представлены в исходном формате PlantUML или Mermaid и дополнительно экспортированы в PNG.
