# Архитектура проекта FlaskBB

## 1. Общая характеристика архитектуры

FlaskBB — веб-приложение для создания и управления интернет-форумом.
Проект разработан на Python с использованием Flask.

Архитектура построена на разделении функциональности по модулям.
Основные компоненты приложения отвечают за аутентификацию,
пользователей, форумы, поиск и административное управление.

Создание приложения реализовано с использованием фабричного
подхода: приложение создаётся функцией `create_app()`.

## 2. Основные точки входа

| Компонент | Файл | Назначение |
|---|---|---|
| Фабрика приложения | `flaskbb/app.py` | Создание и настройка экземпляра FlaskBB |
| WSGI | `wsgi.py` | Создание экземпляра приложения для WSGI-сервера |
| CLI | `flaskbb/cli/main.py` | Команды управления приложением |
| Запуск через Flask | `flaskbb.cli.main:flaskbb` | Точка входа консольной команды |

## 3. Основные модули

| Модуль | Назначение |
|---|---|
| `flaskbb/auth/` | Регистрация, вход, выход, активация аккаунта, восстановление пароля |
| `flaskbb/user/` | Профили, настройки и управление данными пользователей |
| `flaskbb/forum/` | Форумы, категории, темы, сообщения и вложения |
| `flaskbb/management/` | Административная панель, управление пользователями, группами и форумами |
| `flaskbb/search/` | Поиск пользователей, тем и сообщений |
| `flaskbb/plugins/` | Поддержка расширений и плагинов |
| `flaskbb/configs/` | Конфигурации приложения |

## 4. Используемые технологии и зависимости

Основные технологии:

- Python — язык программирования.
- Flask — веб-фреймворк.
- SQLAlchemy и Flask-SQLAlchemy — взаимодействие с базой данных.
- Alembic — миграции структуры базы данных.
- Jinja2 — шаблонизация страниц.
- Celery — механизм фоновых задач.
- Redis — поддерживаемый компонент для кэширования и фоновых задач.
- Click — интерфейс командной строки.
- Pluggy — система расширения приложения с помощью плагинов.

Инструменты разработки:

- uv — управление зависимостями и окружением.
- pytest — автоматизированное тестирование.
- Ruff — проверка и форматирование Python-кода.
- mypy и basedpyright — статическая проверка типов.
- Tox — запуск проверок в разных окружениях.
- Sphinx — генерация документации.

Список зависимостей и настройки инструментов находятся в `pyproject.toml`.
Файл `uv.lock` фиксирует разрешённые версии зависимостей.

## 5. Хранение данных и внешние компоненты

### База данных

Для работы с данными используется SQLAlchemy.
В стандартной конфигурации предусмотрена SQLite.

Также проект содержит настройки для использования PostgreSQL и MySQL.
Миграции базы данных выполняются с помощью Alembic.

### Кэширование

Для кэширования используется Flask-Caching.
В стандартной конфигурации предусмотрен SimpleCache.
Также поддерживается RedisCache.

### Фоновые задачи

В проект интегрирован Celery.
Для брокера сообщений и хранения результатов может использоваться Redis.
Настройки компонентов определяются конфигурацией приложения.

### Почтовые уведомления

Для отправки электронной почты используется Flask-Mail.
Параметры почтового сервера задаются в конфигурации.

### Файлы

В приложении предусмотрена работа с вложениями и аватарами пользователей.
Для обработки изображений используется Pillow.

## 6. Конфигурация приложения

Настройка приложения выполняется при вызове `create_app()` в `flaskbb/app.py`.

Основные конфигурационные файлы:

- `flaskbb/configs/default.py` — стандартные настройки;
- `flaskbb/configs/docker.py` — настройки для Docker-окружения;
- `flaskbb/configs/testing.py` — настройки тестирования;
- `flaskbb.cfg` — локальный конфигурационный файл экземпляра приложения.

Приложение поддерживает переопределение параметров через переменные
окружения.

Локальный конфигурационный файл не должен попадать в Git,
поскольку может содержать секретные данные.

## 7. Взаимодействие компонентов

Общий процесс обработки запроса:

1. Пользователь отправляет HTTP-запрос.
2. Flask принимает запрос и передаёт его соответствующему маршруту.
3. Модуль приложения обрабатывает запрос.
4. При необходимости выполняется обращение к сервисам и моделям.
5. SQLAlchemy обеспечивает взаимодействие с базой данных.
6. Результат передаётся в шаблон Jinja2 или возвращается в виде ответа.
7. Пользователь получает сформированный ответ.

## 8. Инженерные практики

В проекте обнаружены следующие практики:

- автоматизированные тесты на pytest;
- проверка стиля кода с помощью Ruff;
- статическая проверка типов с помощью mypy и basedpyright;
- фиксация зависимостей в `uv.lock`;
- автоматизация проверок с помощью GitHub Actions;
- документация с использованием Sphinx;
- миграции базы данных через Alembic;
- разделение приложения на функциональные модули;
- расширение функциональности через систему плагинов.

В каталоге `.github/workflows/` обнаружены сценарии:
`docker.yaml`, `pre-commit.yaml`, `publish.yaml`, `tests.yml`, `typing.yaml`.

## 9. Вывод

FlaskBB использует модульную архитектуру на основе Flask.
Основная функциональность разделена на независимые области:
аутентификацию, работу с пользователями, форум, поиск и управление.

Использование SQLAlchemy, Alembic, Celery, системы плагинов,
автоматизированных тестов и CI позволяет расширять и сопровождать проект.
